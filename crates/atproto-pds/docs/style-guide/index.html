Foundations

The page itself: how wide it is, what the type does, and how it answers the reader's colour scheme and viewport.

Shell & measure ↑

The column caps at 72rem and is fluid below it: max-width: min(72rem, 100%) is one declaration covering both directions, with no breakpoint deciding which. The gutter scales with the viewport via clamp(0.9rem, 2.5vw, 2rem), and box-sizing: border-box keeps it inside the cap rather than added to it.

Nothing between the shell and the text caps the width. The card fills the shell and its contents fill the card, so this paragraph runs the full measure of the column on a wide display rather than stopping short of the card edge. A line therefore runs longer than typographic convention likes; using the width is the accepted trade.

The one exception is a single-line input, which caps at 34em. A field is filled rather than read, and one stretched across the whole column is a target far larger than the handle going into it. textarea has no cap, because the only ones here hold record JSON.

Everything inherits overflow-wrap: anywhere, so DIDs, AT-URIs, CIDs and scope lists fold instead of widening the page: at://did:plc:iu5fzdrrfrc6kk7vmmatvin2/app.bsky.feed.post/3msw44754okhn

Headings & text ↑

Page title (h1, one per page)

Subtitle under a page title — .sub

Section heading (h2)

The first heading in a card sits flush with the card's padding; later ones keep their top margin. The stylesheet does this — a card does not have to remember to ask for it.

Body prose — plain p. Carries bold for emphasis, links, and inline code for identifiers, header names and anything typed.

Explanatory text — .muted. Used for the sentence under a heading that says what a control does, and for the caveat under a form. By far the most-used class on the site.

Dimmed — .dim. A shade below muted; used for the repeated part of a value where only the tail differs, and for a DID under the handle that names it.
